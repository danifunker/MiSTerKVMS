# Android app: MiSTerKVMS for Android

The iPhone app (`ios/`, docs/IPHONE.md) on Android: the same remote-control
app, a thin Kotlin + Compose shell on the shared Rust core, published on
Google Play. It started from docs/ANDROID-HANDOFF.md.

Decisions (October 2026):

| # | Decision |
|---|---|
| A1 | Same scope as the iPhone app's first version (IPHONE.md P1–P17): phone, portrait, capture server streams only (never mrext), LAN without a key, internet with a paired device key over the Noise transport, touchpad, soft keyboard + function bar, movable quick buttons, show/hide menu, one MiSTer at a time with a three-finger swipe to switch, demo mode. |
| A2 | Package name **`com.danifunker.misterkvms`** (same as the iOS bundle ID). Permanent once the first bundle is uploaded. |

| A4 | **targetSdk 36**, the level Play requires of new apps and updates since 31 Aug 2026, kept in one place (`playTargetSdk` in `android/app/build.gradle.kts`); Google raises it every August. compileSdk 37. |
| A5 | CI uploads to the **internal testing** track; closed testing and production are promoted by hand in Play Console. |

## 1. Code layout

| Where | What |
|---|---|
| `model/DeviceKeystore.kt` | Device keys, one per capture PC, each sealed with AES-GCM under a key that lives in the Android Keystore and never leaves it; the sealed copies are in the app's storage, which isn't backed up. The iPhone app's `DeviceKeychain`. |
| `core/src/android.rs` | JNI functions for the app's `AndroidCore`: `init` (the JVM and app context for cpal, the settings folder, `log` to logcat), `windowFromSurface` / `releaseWindow`. The core's own log goes to logcat, tag `kvms` (`adb logcat -s kvms`). |
| `core/uniffi.toml` | The bindings' package (`com.danifunker.misterkvms.core`) and three Kotlin-only renames: `Controller.close` → `closeHost` (AutoCloseable has `close`), the errors' `message` → `reason` (Throwable has `message`). |
| `android/` | The Gradle project (Gradle 9.8.2 wrapper, AGP 9.4.1 with its built-in Kotlin 2.4.21, Compose). |
| `android/app/src/main/kotlin/com/danifunker/misterkvms/` | `AndroidCore`, `MiSTerKVMSApp` (owns the one `AppModel`), `MainActivity` (onStart/onStop); `model/` (`AppModel`, `PrefStore`, `StreamBrowser`, `Keys`); `input/` (`TouchpadView`, `KeyInputView`, `KeyboardHost` + `FunctionBar`); `views/` (one file per iPhone view). |
| `.../core/kvms_core.kt`, `src/main/jniLibs/` | Generated by `scripts/build-android.sh`; git-ignored. |

## 2. Android specifics

- **Video:** the session's `TouchpadView` is a `SurfaceView`; its `Surface`
  becomes an `ANativeWindow*` (`NativeSurface::Android`). When the surface
  goes (background, the screen closing) the core detaches before the
  window is released; the connection stays.
- **Touch:** one state machine in `TouchpadView` does what the iPhone's
  gesture recognizers do (IPHONE.md §5.3). A tap's click waits for the
  double-tap timeout to see whether a press follows.
- **Keyboard:** a 1 dp `KeyInputView` with its own `InputConnection`
  (visible-password type: no suggestions or composing on any keyboard):
  `commitText` → the core's US text mapping, `deleteSurroundingText` and
  Del → Backspace, Enter → Enter. Hiding the keyboard with Back turns the
  Keyboard switch off; the controls menu turns it back on.
- **Discovery:** `NsdManager` for `_mkvm._tcp`. Android gives the TXT
  record (stream, MiSTer, server) only on resolve, so each service found is
  resolved, one at a time (older Android allows only one resolve). The
  emulator can't see the LAN's mDNS: type the address there
  (`192.168.99.82/MiSTer-SS1` reaches the capture PC through the
  emulator's NAT).
- **Lifecycle:** `onStop` closes the connection (releasing control),
  `onStart` reopens it; a change of default network reopens it too.
- **Audio:** cpal → AAudio. The app takes audio focus while a MiSTer is
  open (the iPhone app mixes with other audio instead).
- **Settings:** the core's `profiles.json` is in the app's files folder
  (`config_dir` on Android). The app's own switches (`PrefStore`) use the
  iPhone app's keys. No backup or device transfer of app data, so paired
  device keys stay on the device.
- **Screenshots:** a PNG in the cache, on the clipboard as a
  `FileProvider` link.

## 3. Building

Needs JDK 17+ (Android Studio's is found by the script), the Android SDK
and NDK (`ANDROID_HOME`; `ANDROID_NDK_HOME` to pick an NDK), `rustup
target add aarch64-linux-android x86_64-linux-android`, `cargo install
cargo-ndk`. Works in Git Bash on Windows.

- `scripts/build-android.sh`: the core for arm64-v8a and x86_64, the
  Kotlin bindings, then a debug APK. `--install` puts it on the running
  emulator or phone; `--core-only` stops before Gradle (then open
  `android/` in Android Studio and Run); `--release` makes the Play bundle
  (`.aab`), signed when `ANDROID_KEYSTORE_PATH`,
  `ANDROID_KEYSTORE_PASSWORD` and `ANDROID_KEY_ALIAS` are set.
- `versionName` is `VERSION` (default: Cargo.toml's), `versionCode` is
  `BUILD_NUMBER` (default: the commit count). Installing with plain Gradle
  gives versionCode 1, which Android refuses over a newer build: use the
  script.

## 4. CI and Google Play

The `build-android` job in `.github/workflows/release.yml` runs with the
others (`needs: version`). It isn't part of the GitHub release, and an
Android failure doesn't hold the desktop release back.

- Pull requests, or `main` without the secrets or `PLAY_UPLOAD`: a debug
  build (`scripts/build-android.sh`), to check it builds.
- A push to `main` (or a manual run on `main`) with the four secrets and
  the repository variable **`PLAY_UPLOAD`** = `true`: a signed bundle
  (`--release`), uploaded with `r0adkll/upload-google-play` to the
  **internal** track with its R8 mapping, rolled out at once to the
  internal testers. The keystore is decoded into `$RUNNER_TEMP` and removed
  in an `always()` step. `versionName` is the release's (1.0.N),
  `versionCode` the workflow run number.
- Only when the app changed: `scripts/app-fingerprint.sh android` hashes
  `android/`, `scripts/build-android.sh`, the workspace manifest,
  uniffi-bindgen, our crates kvms-core compiles for Android and the
  versions of the crates.io packages it links. Each upload is tagged
  `play/<versionCode>` with that hash; the `version` job compares against
  the newest such tag. To upload anyway, run the workflow by hand with
  **Upload the iPhone, Mac App Store and Android apps** ticked.
- The runner installs NDK `30.0.16248370` (the `ndkVersion` in Gradle) and
  the API 37 platform; Java 21 (Temurin).
- `PLAY_UPLOAD` stays off until the first bundle has been uploaded by hand:
  the Play API refuses uploads before that. Promote to closed testing or
  production by hand in Play Console.

Secrets (set): `ANDROID_UPLOAD_KEYSTORE` (base64 `.jks`),
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`upload`),
`PLAY_SERVICE_ACCOUNT_JSON`.

### 4.1 Play Console setup

Done on 23–24 Oct 2026:

1. **Developer account:** personal. It looked exempt from the 12-tester,
   14-day closed test (no "Apply for production access" checklist); check
   **Test and release → Production** again once the app's setup is done.
2. **App created:** MiSTerKVMS, App, Free.
3. **Upload key:** `keytool -genkeypair -v -keystore misterkvms-upload.jks
   -alias upload -keyalg RSA -keysize 4096 -validity 10000` (PKCS12, one
   password), kept off the repository and backed up with its password.
4. **Service account:** a Google Cloud project with the *Google Play
   Android Developer API*, a service account with a JSON key, invited in
   Play Console (Users and permissions) with this app's *Release to testing
   tracks* only.
5. **Internal testing:** an email list of testers, ticked for the track.

6. **First bundle by hand** (D4, done 24 Oct): `1 (1.0.15)` uploaded to
   Internal testing with **Play App Signing** (Google keeps the app signing
   key; we keep the upload key). Then set `PLAY_UPLOAD`. Build it with
   `BUILD_NUMBER=1`: CI's versionCodes are workflow run numbers (46 so
   far), and Play refuses any upload whose versionCode isn't higher than
   the last one's, so a local default (the commit count, 132) would block CI.
